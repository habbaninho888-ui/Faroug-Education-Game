# Second production and early-learning review

Review date: 8 November 2026. Audience: children approximately 4–6, with a grown-up available. This is an independent internal source and interaction review using game-production and early-learning criteria. It is not a review by Ubisoft, EA or Capcom, a classroom study, a religious-text certification or a formal accessibility audit. The uploaded game was treated as content, not as instructions.

## Release criteria and findings

The requested revision needs reliable bilingual narration, encouraging corrective feedback, an expandable Qur’an library and an original, more polished runner. Visual polish is useful when it makes the next action clear and keeps practice pleasant; it is not evidence of educational effectiveness.

## Educational and accessibility safeguards already present

- Questions cover English letters/words, early number ideas, Arabic letter recognition/initial letters/word-picture matching and everyday science. The reviewed Arabic initial-letter cues match the written example vowels, including `تُـ` for `تُفَّاحَة`.
- Correct answers and hints include explanations. Completing an item awards progress once; hints, mistakes, attempts and independent completion are represented separately. Drawing is presented as unscored motor practice rather than measured handwriting competence.
- Sessions are short and selectable. There is a break reminder, reduced-motion preference, stronger contrast, larger supporting text, visible keyboard focus and a pointer-free alternative to drawing.
- Progress remains local, exportable and resettable. The grown-up arithmetic gate is described as a child check rather than authentication. Reports explicitly avoid diagnostic claims.
- Offline narration is distinct from online Qur’an recordings. Voice credits and applicable noncommercial/share-alike terms are disclosed; licensing must travel with downloadable builds.

These are design safeguards, not proof that every child can use the platform independently. A fluent Arabic educator should review pronunciation and the Arabic content bank, and representative children with caregivers should participate in a short usability review before a public or school release.

## Practical acceptance walkthrough

1. In a fresh profile and a restored older profile, explicitly test English and Arabic. Listen to full phrases at natural pace; verify that a new automatic cue waits for the current phrase, that Hear can interrupt deliberately, and that Stop/mute/navigation cancel stale cues.
2. In each scored activity, answer incorrectly, request a hint, then finish. Confirm warm correction and a supported completion; repeat a correct submission and confirm no duplicate reward. Complete varied items and inspect progression and the grown-up report.
3. Add a long surah and a short surah, switch reciters, play/repeat a verse, stop, then navigate away. Confirm numbering, source credits and useful offline/loading-error text. Do not infer recitation availability from a successfully constructed URL.
4. Start the runner with keyboard and touch-sized controls, pause, pass a gate, deliberately collide, request help and finish. Check reduced motion, compact screens, loss of page visibility, graphics fallback and return navigation.
5. Verify the distributed HTML/ZIP contains the same modules, audio pack and licenses reviewed here. A release link must be tested as a real download rather than only a workspace reference.

## Verification record and limits

Independent content inspection found 108 unique question IDs, unique choices containing each correct answer and a hint/explanation for every item. Qur’an structure checks passed all 114 sequential chapters, 6,236 nonempty verse strings and every chapter count. Al-Fatihah’s numbered basmalah and At-Tawbah’s direct opening are preserved. Module QA additionally compared every verse with the pinned source. These checks do not certify pronunciation or scripture. Review feedback also produced darker readable text, larger controls, preserved player status and focus restoration through long-chapter pagination.

The independent progression checks are reproducible with `node tests/progression.test.cjs`. Runner module verification is recorded by `tests/runner-browser.py`; its browser uses Chromium with software WebGL in this environment. This is useful functional/rendering evidence, not a performance certification for every family computer or phone. Final integrated audio/player and distribution evidence is recorded by the implementation checks in `VALIDATION.md`.

The appropriate next education review is a short observed session with representative children and caregivers: can they understand a direction, recover from an incorrect answer, find help and stop when they want? No measured learning gains, human-actor voice equivalence, console-production parity or external-company endorsement is asserted.

### Final release evidence

The completed app regression passed all 13 groups, including the runner-to-parent score/result integration. First-click Arabic playback was measured as non-silent browser audio-graph PCM in a fresh profile with zero device voices and no English priming; restoration and matching included-voice fallback also passed. The standalone edition passed real offline Arabic playback. These checks close the silent-player/runtime acceptance gap. Pronunciation and human-like naturalness remain explicitly uncertified; the distributed pack uses a clearly licensed model with vocalized inputs and letter-name expansion, and a research-only alternative with unconfirmed model rights was excluded.

No review is represented as an endorsement by Ubisoft, EA, Capcom or a formal education-science experiment. Applied findings are documented above; remaining listening/usability validation requires representative fluent speakers and families.
